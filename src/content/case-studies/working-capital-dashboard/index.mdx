## Business case

The working capital numbers (DSO, DPO, DIO and the cash conversion cycle) were <Pain>compiled by hand</Pain> from system exports every month. The report was reviewed once, then <Pain>forgotten until the next one</Pain>.

There was a quieter problem too. The colour coding followed the direction of movement, not the direction of benefit. A fall was green and a rise was red, so <Pain>a falling DPO looked good</Pain>, when paying suppliers faster actually ties up cash.

A dashboard without an operating rhythm is just a report. The fix had to cover both: less time preparing the numbers, and a monthly forum where each number has an owner and an action.

### The dashboard

Each KPI tile shows the current value, a six-month sparkline, and the change since last month. The delta colour follows each metric's direction of benefit. Switch the toggle to see the original mistake: DPO fell by 3 days and turns green under "Color by movement", even though it is unfavorable.

### The colour rule

The whole fix is one function. Each metric carries a `better` flag, and the colour comes from comparing the movement to it.

<CodeBlock
  lang="ts"
  filename="delta-color.ts"
  highlight={[8, 9]}
  code={`
type Better = 'up' | 'down';
type Tone = 'good' | 'bad' | 'flat';

// Colour by direction of BENEFIT, not direction of movement.
export function deltaTone(prev: number, cur: number, better: Better): Tone {
  const change = cur - prev;
  if (change === 0) return 'flat';
  const movedUp = change > 0;
  return movedUp === (better === 'up') ? 'good' : 'bad';
}

deltaTone(58, 55, 'up');   // DPO fell: 'bad'
deltaTone(46, 44, 'down'); // DSO fell: 'good'
`}
/>

## Results

Preparing the month now takes <Win>about an hour instead of most of a day</Win>. <Win>Every metric has a named owner</Win>, and the review starts with last month's open actions, so the numbers lead to decisions instead of a slide that gets filed away. Nobody misreads a falling DPO as good news anymore.
